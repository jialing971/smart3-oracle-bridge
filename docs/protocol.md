# 协议说明

## 角色与传输

- SMART3 作为 **TCP 客户端**主动连接本程序。
- 本程序是 **TCP 服务端**，监听 `tcp.host:tcp.port`（默认 `127.0.0.1:1024`）。
- 传输层为明文 TCP，不提供 TLS、客户端证书或来源认证。
- 本程序不主动向客户端发送 ACK/NACK；报文是否写入成功只体现在本程序日志中。

## 报文格式

报文是**逗号分隔的纯文本**，默认编码 UTF-8：

```text
字段0,字段1,字段2,字段3,字段4,字段5,字段6
```

- 分隔符由 `protocol.separator` 配置，默认是 `,`。
- 这**不是标准 CSV**：不支持字段内包含逗号，也不支持双引号转义。字段内容里出现逗号会被拆成多个字段。
- 每个字段两端会执行 `strip()`，首尾空白会被去掉。
- 缺少的尾部字段按空字符串处理。
- 只有 `field_mapping` 中标记为 `required: true` 的字段会做非空校验；默认只有 `barcode` 必填。
- 单条报文超过 `protocol.max_message_bytes` 会被拒绝并记录日志。

默认字段顺序（与 `config/default_config.json` 一致）：

| index | 列名 | 必填 | 说明 |
| --- | --- | --- | --- |
| 0 | `barcode` | 是 | 条码 |
| 1 | `image_path` | 否 | 图片路径（仅存字符串，不上传图片） |
| 2 | `result_code` | 否 | 结果代码 |
| 3 | `employee_id` | 否 | 人员标识 |
| 4 | `station_id` | 否 | 工位标识 |
| 5 | `event_date_str` | 否 | 日期字符串 |
| 6 | `event_time_str` | 否 | 时间字符串 |

示例（全部为虚构数据）：

```text
BC-EXAMPLE-0001,/images/EXAMPLE0001.jpg,OK,E1001,ST01,2026-10-29,08:30:00
BC-EXAMPLE-0002,/images/EXAMPLE0002.jpg,NG,E1002,ST02,2026-10-29,08:31:15
```

如果只需要部分字段，也要按位置留空，例如只发条码和图片路径：

```text
BC-EXAMPLE-0003,/images/EXAMPLE0003.jpg
```

## 报文边界

TCP 是字节流，没有“一条消息”的天然边界。程序对结束符有两种行为：

### 1. 空结束符（默认，兼容旧用法）

`"message_terminator": ""`

- 每次 `recv` 收到的数据被当作**一条完整报文**处理后清空缓冲。
- 这是为了兼容旧版 SMART3 的发送方式。
- 风险：如果一次报文被拆成多个 TCP 包，会被当成多条不完整报文；如果多条报文被合并到一个包，会被当成一条。实际是否可用取决于发送端每次写入的节奏和网络。
- 不推荐在不可靠网络或高频率场景下依赖此模式。

### 2. 指定结束符

```json
"message_terminator": "\n"
```

- SMART3 必须在每条报文末尾同步发送该结束符（上例为换行）。
- 程序按结束符切分缓冲，逐条处理，可缓解粘包/半包问题。
- 当前实现是**先按 `recv` 分块解码 UTF-8，再拼接到文本缓冲**。如果一个多字节字符恰好跨两个 TCP 包，`decode` 会失败，程序记录“解码失败”并断开该客户端。因此：
  - 字段内容建议使用 ASCII；
  - 中文等非 ASCII 内容在分包时仍可能失败；
  - 此限制尚未修复。

## 处理与写入

对每条成功解析的报文：

1. 按 `field_mapping` 生成列值；
2. 执行一次参数绑定的 `INSERT`；
3. 立即 `commit`；
4. 写入 INFO 日志（包含条码）。

异常行为：

- 解析失败（必填字段为空、超长等）：记录错误日志，丢弃该条报文，不回复客户端。
- Oracle 驱动异常：关闭当前连接，自动重连并**重试一次**。
- 重试仍失败：记录日志，丢弃该条报文；没有持久队列或失败补发。
- 如果第一次 `INSERT` 实际已提交、但客户端在收到提交确认前发生网络/驱动异常，重试可能造成**重复记录**。目标表应建立唯一约束，或在业务侧设计幂等键。

## 连接与超时

- `tcp.max_clients` 限制并发客户端数；超出的连接会被接受后立即关闭。
- `tcp.keep_alive_seconds` 是 `recv` 的超时时间。超时后程序**继续等待**，不会断开空闲连接，也不是 TCP keepalive 探活。
- 程序未设置数据库连接/语句超时；数据库无响应时，对应客户端线程可能长时间阻塞。
- 服务停止时会关闭监听套接字和客户端连接，但不会等待所有入库线程自然结束（线程为 daemon）。
