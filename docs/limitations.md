# 已知限制与验证边界

本文档如实记录当前代码的可靠性、安全性限制和本次发布前的验证范围。未列出的场景不代表已经验证；涉及生产使用时，请先在隔离环境完成现场验收。

## 1. 本次验证范围

本次发布前只进行了**离线检查**，没有连接真实 SMART3、Oracle 数据库或生产网络：

- 对 `main.py` 与 `src/**/*.py` 共 19 个 Python 文件做 AST 语法检查；
- 解析 `config/default_config.json`，执行配置模型转换与 `_validate_config` 校验；
- 用虚构报文验证解析成功、字段两端 `strip()`、缺失尾部字段为空；
- 验证缺少必填 `barcode` 时抛出异常；
- 根据默认配置生成参数化 INSERT 语句，确认列顺序和 `:1`…`:7` 绑定参数；
- 比对 `src/**/*.py` 与原项目文件的 SHA-256，确认源码未被修改（全部一致）。
- 在临时配置目录下验证首次生成运行配置、保存与重新加载；
- 验证报文超长及非法 SQL 标识符会被拒绝；
- 使用临时配置完成隐藏窗口的 GUI 初始化，未启动 TCP 服务、未进行界面交互。

**未验证**：

- 未启动 TCP 服务，未做真实 socket 收包、粘包/拆包、并发连接测试；
- 未连接任何 Oracle 数据库，未执行 INSERT/commit，未验证 DSN、账号权限、字符集、NLS、字段长度；
- 未连接真实 SMART3，未做现场协议联调；
- 未运行图形界面交互测试（启动/停止/设置/测试连接）；
- 未运行 `build.bat`，未验证 PyInstaller 打包产物或 EXE。

验证环境：Windows，Python 3.12.14（Codex 内置运行时），python-oracledb 4.0.0。实际部署环境的 Python、oracledb 与 Oracle 版本可能不同，需重新验证。

## 2. 协议与报文可靠性

- 默认 `message_terminator` 为空，每次 `recv` 的数据被当成一条完整报文。TCP 没有消息边界，粘包或拆包时可能把多条报文合并、把一条报文拆开。
- 配置结束符（如 `"\n"`）后可按结束符切分缓冲，但解码仍是在每个 `recv` 块上独立进行的。多字节字符（如中文）跨 TCP 包时 `UnicodeDecodeError` 会导致该客户端被断开。
- 不是标准 CSV：不支持字段内逗号、引号转义或字段内换行。
- 没有 ACK/NACK，发送端无法从协议层确认入库结果；失败只记录本地日志。
- 除必填字段外不做格式、长度、编码范围或业务规则校验；超长值是否被数据库拒绝取决于目标列定义。
- 没有持久化队列、失败补发、离线缓存或重放机制。

## 3. 数据库写入可靠性

- 每条记录执行一次 `INSERT` 并立即 `commit`，没有批量事务或幂等键。
- Oracle 驱动异常时关闭连接、重连并重试一次。若第一次 `INSERT` 已在数据库提交但客户端未收到确认，重试可能写入重复记录；目标表应建立唯一约束或在业务侧实现幂等。
- 重试仍失败时只记录错误日志，该条数据丢弃，不会回传给发送端。
- 程序未设置数据库连接超时、语句超时或 `call_timeout`；数据库无响应时，客户端工作线程可能长期阻塞。
- `ping()` 只能探测连接可用性，不能保证后续 INSERT 一定成功；存在检查后失效的竞态。
- 没有连接池、重连退避或熔断；每个客户端线程独立持有一个连接。
- 不自动建表、不校验表结构、不转换日期/时间类型、不上传图片文件，只保存路径字符串。

## 4. 服务与界面

- TCP `bind`/`listen` 在后台线程执行，`Service.start()` 在线程启动后立即向界面报告“服务运行中”。如果端口被占用或地址非法，后台线程会抛出未处理异常退出，界面仍可能显示运行中，而实际监听已失败。`bind`/`listen` 不在处理 `accept` 的 `OSError` 捕获范围内，界面不会自动纠正状态。
- `_on_start` 只能捕获 `Service.start()` 同步抛出的异常，无法捕获后台线程中的 `bind` 失败。
- 停止服务会关闭监听套接字和客户端连接，但不会 join 所有客户端入库线程；这些线程是 daemon，可能仍有写入在途。程序退出时不会等待它们完成。
- 客户端线程数量受 `max_clients` 限制；达到上限时新连接会被接受后立即关闭，发送端通常只能看到连接被断开。
- “测试数据库连接”在 GUI 主线程中同步执行；数据库网络慢或不可达时，界面可能暂时无响应。
- 设置保存后不会热更新正在运行的服务，需要停止并重新启动服务。
- 修改 `protocol` 和 `field_mapping` 必须手工编辑 `config.json`，界面不提供这些字段的编辑入口。
- 配置读取失败（JSON 格式错误、字段非法、必填配置缺失）会阻止程序启动；没有图形化的配置修复入口。
- 日志界面只保留最近 200 行，完整记录以文件为准；高频日志采用批量刷新，极端情况下界面显示可能滞后。

## 5. 安全限制

- 默认管理员密码为 `admin`，仅作为本地设置入口的门槛，不构成强访问控制。
- 管理员密码使用**不加盐的 SHA-256** 保存，可被离线暴力破解；没有密码复杂度、过期或审计策略。
- 登录失败 3 次只会关闭当前设置窗口，重新打开对话框后计数清零，不构成持久锁定。
- 数据库口令以**明文**保存在 `config/config.json`，程序不支持环境变量或系统密钥库。
- 程序不提供 TCP 层 TLS、客户端证书、来源 IP 白名单或报文签名；监听 `0.0.0.0` 时任何可达主机都能发送数据。
- 日志可能包含条码、图片路径和数据库错误信息，属于潜在敏感数据。
- 程序不会主动清理日志或运行配置，交付/发布前需要人工检查。

## 6. 打包与分发

- `build.bat` 会执行 `pip install -U pip` 并安装/更新 `requirements.txt` 与 PyInstaller，会修改当前 Python 环境；这是用户手动可选操作。
- 本次发布没有运行 `build.bat`，没有验证 `dist/FormassyBridge/` 或发布 ZIP 的可用性。
- 本次使用的内置 Python 运行时导入 PyInstaller 时，提示缺少可用的 `pywin32-ctypes`，因此不能声称 EXE 打包已通过。
- `build.spec` 使用 `collect_all` 收集 oracledb 和 cryptography 的数据/二进制；不同版本组合下的打包结果未验证。
- 已从 `build.bat` 删除复制 `config/config.json` 的步骤；压缩前若目标目录存在运行配置或 `logs/`，脚本会中止并保留原文件。模板被手工写入真实凭据或其他路径含有敏感文件的情况仍须人工检查。历史 ZIP 不会因为本次中止自动移除，不应继续分发。

## 7. 兼容性

- 仅在 Windows 上的 Tkinter 环境设计；未验证 Linux/macOS。
- 文档要求 Python 3.10+；本次只在 Python 3.12.14 上做离线检查，未逐一验证其他版本。
- oracledb 按官方文档使用 Thin 模式，官方写明支持 Oracle Database 12.1+；本程序未实现 Thick 初始化，不宣称支持 11g 或其他未列出的版本。
- 程序把 schema/table/列名转为大写，使用带引号的大小写敏感对象名不受支持。
- 未处理时区、NLS 日期格式、字符集转换等现场差异。
