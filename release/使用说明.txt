FormassyBridge 使用说明
SMART3 → Oracle 数据网关（源码版本 0.1.0）
==================================================

一、这是什么
--------------------------------------------------
FormassyBridge 在本机监听一个 TCP 端口，接收 SMART3 发来的逗号分隔文本，
按配置解析字段后逐条写入 Oracle 数据库。界面用于修改 TCP/数据库参数、
启停服务和查看日志。

本程序是非官方项目，与 SMART3、Oracle 厂商无隶属或授权关系。
SMART3、Oracle 本体及第三方依赖不随本发布提供。

二、运行前准备
--------------------------------------------------
1. 本发布目录需要包含 FormassyBridge.exe（由 build.bat 打包生成）。
   注意：本次源码发布没有验证 EXE 打包产物；如使用自行打包的 EXE，
   请先在测试环境完成验证。
2. 目标 Oracle 数据库已创建业务表，并准备好具备登录和 INSERT 权限的账号。
   程序不会自动建表，也不会上传图片，只保存图片路径字符串。
3. 确认本机到数据库的网络、防火墙放行情况。
4. 使用 python-oracledb Thin 模式，无需安装 Oracle Client。

三、首次启动
--------------------------------------------------
1. 将整个发布文件夹解压到本地可写目录，不要在压缩包内直接运行。
2. 双击“启动 FormassyBridge.bat”。
3. 首次启动会在 config 目录下生成 config.json（内容来自 default_config.json）。
4. 点击界面“设置”：
   - 默认管理员密码：admin
   - 填写 TCP 监听地址/端口、Oracle 用户名/口令/DSN/schema/表名
   - 可点“测试数据库连接”手动验证（只建立并关闭连接，不执行 SQL）
   - 保存后，如服务正在运行，需要停止并重新启动服务才能生效
5. 回到主界面点击“启动服务”，让 SMART3 作为 TCP 客户端连接本机端口。

如果需要在别的机器访问，tcp.host 要改为 0.0.0.0 或指定网卡地址，
并在防火墙中仅放行可信来源。

四、安全提醒（重要）
--------------------------------------------------
1. config/config.json 保存数据库明文口令，属于敏感文件。
   - 不要发给无关人员；
   - 不要提交到 Git 或代码仓库；
   - 建议用文件系统权限限制访问；
   - 程序不支持从环境变量读取口令。
2. 首次运行后请立即修改默认管理员密码。该密码只是本地设置入口的门槛，
   使用不加盐的 SHA-256 保存，不是强安全保护。
3. 程序不提供 TLS、客户端认证或来源 IP 校验。监听 0.0.0.0 时，
   任何能访问该端口的主机都可以发送数据，请用网络隔离/防火墙限制。
4. logs/app.log 可能包含条码和错误详情，同样按敏感信息管理。
5. 制作或转交发布包前，必须检查目录中不包含：
   - config/config.json（运行配置，含口令）
   - logs/ 目录及任何日志文件
   - 本机测试产生的其他临时文件

五、日常操作
--------------------------------------------------
- 启动服务：主界面“启动服务”。
- 停止服务：先点“停止服务”，等待状态变为“停止”，再关闭窗口。
- 查看日志：界面日志区显示最近 200 行；完整日志在 logs/app.log（自动轮转）。
- 修改 TCP/数据库/管理员密码：设置对话框；保存后重启服务生效。
- 修改协议分隔符、结束符、字段映射：只能手工编辑 config/config.json，
  保存后重启服务生效。字段映射中的列名必须是数据库表中已存在的列。

六、常见问题
--------------------------------------------------
1. 点击启动后界面显示“运行中”，但端口没有监听？
   已知限制：监听失败发生在后台线程，界面可能误显示运行中。
   请检查端口是否被占用、监听地址是否合法，并查看 logs/app.log。
2. 数据库连接失败？
   检查用户名/口令/DSN、网络连通性、账号是否具备登录和 INSERT 权限。
   DSN 示例格式：host:port/service_name。
3. SMART3 数据没有入库？
   检查 SMART3 是否作为 TCP 客户端连接、报文是否以逗号分隔、
   barcode 是否非空、结束符设置是否与发送端一致；查看日志中的解析/写入错误。
4. 重复数据？
   程序每条 INSERT 后立即提交；驱动异常时会重连并重试一次，
   如果第一次提交实际成功但确认丢失，可能产生重复记录。
   建议在数据库层建立唯一约束或在业务侧做幂等设计。
5. 中文乱码或客户端被断开？
   程序按 TCP 分块解码 UTF-8，多字节字符跨包时可能解码失败。
   建议字段使用 ASCII；或调整发送端发送节奏。
